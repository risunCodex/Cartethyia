# Proposal — Dashboard i18n (native / fast)

Status: proposed — not yet implemented (target: next session)
Scope: `dashboard/` only. Backend contracts, `/console/api` response messages, and
share-page server metadata are out of scope except where noted.
Languages: **English (source of truth) + Indonesian** now; more locales later by
adding dictionary files only.
Carried constraints: browser-safe bundle, no new runtime dependency,
token/utility styling untouched, localStorage keys namespaced
`cartethyia:<area>:<name>`.

---

## 1. Code survey (grounding, measured 2026-10-31)

- **97 file `.tsx`**, **74 file `.ts`** under `dashboard/src`
- **±2.400 user-facing text fragments**: JSX text nodes, `aria-label`,
  `placeholder`, `title`, `label`, `toast.success/error`
- 13 feature areas: cli-tools, customization, logs, overview, provider-detail,
  providers, proxy, quota, routing, session, settings, studio, usage
- Largest monoliths: `StudioPage.tsx` 52KB, `ApiKeyForm.tsx` 49KB,
  `ProvidersPage.tsx` 45KB, `Models.tsx` 42KB, `QuotaPage.tsx` 39KB,
  `ChatBubble.tsx` 35KB

**Cost shape:** the translation itself is cheap (EN→ID in one pass). The bulk is
mechanically touching 2.400+ inline literals across 97 files, plus tests that
assert English literals.

## 2. Design (native, no runtime dependency)

### 2.1 Why not react-i18next / formatjs

Runtime i18n machinery (provider tree, hook subscriptions, ICU message format)
brings re-render overhead and interop we do not need:

- our lookup is a plain key → string map, read **synchronously**
- numbers/dates are already handled by utility classes (`tabular-nums`) or can
  use native `Intl.NumberFormat`
- plural needs are small (counts of accounts/models) — one `tCount(key, n)`
  helper with `{one}` / `{other}` forms is enough

### 2.2 Structure

```
dashboard/src/i18n/
  lang.ts        — type Locale ("en" | "id"), locale list
  store.ts       — read/write `cartethyia:i18n:lang`, change event, <html data-lang>
  t.ts           — t(), tCount(), tNumber()/tDate() helpers (plain functions)
  dictionary.ts  — merges locale files; dict type derived from `en`
  en.ts          — English dictionary (generated by the sweep)
  id.ts          — Indonesian dictionary
```

- **EN is the source of truth.** The dictionary type is derived from `en`
  (`type Dict = typeof en;`) — a key missing from `id` is a compile error.
- **Fallback:** if `id` lacks a translation, `t()` renders the English value.
  Never render a bare key or an empty string.
- **Not hook-first:** `t()` is an imported plain function used anywhere (props,
  event handlers, plain helpers). Locale switching repaints once: `store.ts`
  sets `<html data-lang>` and dispatches a CustomEvent — the same pattern
  `dashboard/src/features/customization/settings.ts` already uses for `data-blur-*` — and the app
  shell keys its top subtree on the locale so React rebuilds text once.
- **Bundle:** both locales ship in the main bundle (roughly 60–100KB raw,
  compresses well). No dynamic import in phase 1; introduce per-locale chunks
  only when a 3rd locale arrives.
- Key naming: `area.component.slot` (e.g. `proxy.pools.createButton`,
  `studio.composer.send`). Keys are stable identifiers — do not rename keys
  when changing copy.

### 2.3 Language switcher

- A `Select` on the **Settings** page (not Customization — this is behavior,
  not cosmetics).
- Persists `cartethyia:i18n:lang` (`"en" | "id"`); read synchronously at boot
  before first render (same pattern as `dashboard/src/features/customization/settings.ts`) so there is **no EN flash**
  on reload.

## 3. Work phasing (one commit per phase, matching repo style)

| Phase | Content | Duration | Commits |
|---|---|---|---|
| 1 | Infra (`i18n/lang.ts`, `store.ts`, `t.ts`, `dictionary.ts`, `en.ts` skeleton), `tCount`, switcher in Settings, PoC on one page (**Overview** — easiest to verify visually), unit tests for the store/t helpers | ½ session | 1 |
| 2 | Shell: sidebar/nav (`dashboard/src/apps/console/shell.tsx`), topbar, user card, sign-in/setup pages, global toast copy, customization page | ½–1 session | 2 |
| 3 | High-traffic features: `providers/` (incl. `ApiKeyForm`, `Models`), `proxy/`, `quota/`, `usage/`, `session/`, `settings/` | 1–2 sessions | 3–5 (per area) |
| 4 | Remaining sweep: `studio/` (StudioPage, ChatBubble, Composer), `routing/`, `cli-tools/`, `logs/`, `provider-detail/` | 1–2 sessions | 6–8 |
| 5 | Test migration + browser pass + leftover audit (scan `features/` + `components/` for missed JSX literals) | ½–1 session | 9 |

**Total realistic: ±5–6 focused sessions ≈ 1–2 days of intensive work.**
Phases 1–3 alone cover every page an operator touches daily — stopping there is
a valid milestone, with the rest following later.

### 3.1 Deliberately excluded

- **`apps/share/**`** — public pages whose title/OG/Twitter metadata is injected
  server-side; copy here stays English. Indonesian share pages are recorded as
  future work only if requested.
- **API-driven strings** — provider display names from
  `src/providers/provider-metadata.ts` and gateway error messages arrive from
  `/console/api`; translating them is a backend concern with a separate
  decision. The dashboard translates only its own labels, buttons, toasts, and
  descriptions.

## 4. Standing rules (decide once, don't relitigate)

1. **Test assertions** keep English literals (default locale is `en`); only a
   test that explicitly switches locale uses keys. No runtime locale juggling
   in tests.
2. **Interpolation:** full sentences per key with `{name}` slots — never
   concatenate translated fragments; word order differs per locale.
3. **aria-labels are content:** the sweep covers accessibility labels too.
4. **Dictionary hygiene:** no user data, no HTML in values; values are plain
   UI text only.

---

## 5. Definition of done

- `tsc --noEmit` green; dashboard suites green; browser verification per
  `verification.md` for each phase that claims a visible change
- Switching language in Settings updates every page **without reload**
  (CustomEvent-driven);
- Hard refresh keeps the chosen language with **no EN flash** (store read
  pre-render)
- Grep audit: no unintended English literal fragments remain in swept areas
- A short `documentation/features/` note: i18n behavior, key policy, how to add
  a new locale

---

## 6. Risks

| Risk | Mitigation |
|---|---|
| Key drift between page and dictionary | `Dict` type derived from `en`; typed `t()`; EN fallback |
| Bundle growth from duplicated copy | review each `en.ts` pass for duplicate strings; consolidate keys |
| Accidentally translating API text | the 3.1 boundary is enforced at review |
| Too large for one review | one commit per phase |
| Missed locale rendering (Select option labels etc.) | browser pass each session |
