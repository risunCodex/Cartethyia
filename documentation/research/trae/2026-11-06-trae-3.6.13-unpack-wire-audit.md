## 2. Source of truth: `ai_agent.dll` (Rust harness)

The chat/agent endpoints are **not** in the JS bundles (`out/main.js`,
`out/vs/workbench/*`, `node_modules/@byted-icube/*` — string scans found zero
hits for `llm_utils_chat`, `llm_raw_chat`, `batch_get_detail_param`). They live
in the native Rust harness:

- `modules/ai-agent/ai_agent.dll` — endpoint table + call sites (20 hits for
  `llm_utils_chat`, 20 for `api/agent/v3`, 20 for `api/ide/v1`)
- `modules/ai-agent/harness.dll` — mode map (`"deepseek-v4.1-flash": "default"`),
  no request spec
- Rust source paths embedded in debug/panic strings confirm authorship:
  `apps\icube_server_rs\modules\ai-agent\src\domain\model\llm_stream.rs`,
  `apps\icube_server_rs\crates\hub_net\src\http_transport.rs`, etc.

## 4. Headers and auth

Evidence from `ai_agent.dll` (hub_net + http) and `out/main.js`:

- **`Authorization: Cloud-IDE-JWT <token>`** — used across app surfaces (upload
  auth, report creation, hub request fallback). Matches the adapter.
- **`x-ide-token`** — present in `[HubNetService] auth headers updated` next to
  `Authorization`; appears in `http.rs:4296` filter list alongside
  `x-web-id`, `x-user-real-ip`, `token`, `secret`, `credential`, `apikey`,
  `api-key`. The hub net transport sends it; the data-plane chat surface in the
  adapter does not (b6786417 baseline).
- `x-frontier-id` — frontier (WebSocket) transport header.
- `x-tt-logid` — request log id.

### 5.1 Error code semantics (observed)

| Code | Meaning | Adapter mapping |
|---|---|---|
| `1001` | auth / region mismatch on pay host | `authentication_failed` 401 |
| `4008` / “exceeded the quota” | free quota exhausted | `quota_exceeded` 429 |
| `1005 {"plan":N}` | model requires a plan the account lacks | `quota_exceeded` 429 (entitlement) |
| `4015` | model/account refused (entitlement; token still valid) | `quota_exceeded` 429 |
