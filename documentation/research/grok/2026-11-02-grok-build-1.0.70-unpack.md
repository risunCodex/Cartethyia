# Grok Build CLI — binary unpack evidence (1.0.70, macOS Silicon)

Status: **verified static unpack** (2026-11-02). Wire behavior verified against
the shipped `grok` CLI binary, not public source. For the checked-in adapter
comparison, see the "Adapter parity" section at the bottom.

## Pinned object

- **Product:** Grok Build CLI (`grok` / `agent`).
- **Version:** `1.0.70` — pinned from the official stable channel pointer
  `https://storage.googleapis.com/grok-build-public-artifacts/cli/stable`
  (also `https://x.ai/cli/stable`). Matches npm `@xai-official/grok@1.0.70`.
- **Artifact:** `grok-1.0.70-macos-aarch64` (GCS).
- **Container:** gzip (`grok-1.0.70-macos-aarch64.gz`, 72.5 MB compressed /
  179.1 MB raw). Plain artifact exists too; `.zst` also published.
- **Binary:** Mach-O 64-bit arm64 executable (magic `CF FA ED FE 0C`), PIE,
  TWOLEVEL, HAS_TLV_DESCRIPTORS. Rust — source paths leak through panic/event
  strings (e.g. `crates/codegen/xai-grok-sampler/src/stream/responses.rs`,
  `xai-grok-shell`, `xai-grok-workspace`, `xai-grok-pager`,
  `xai-grok-cloud-config`, `xai-grok-tools`).

## Method

- Downloaded the official installer artifact (no install; no execution).
- Decompressed with `gzip -dk`.
- Streamed printable-ASCII extraction (32 MiB chunks, overlap) → 152k strings.
- Grep for URLs, header names, struct field names, tool names, event names.

## What was proven

### Endpoint / backend

- Default proxy: `https://cli-chat-proxy.grok.com/v1` (env override
  `GROK_CLI_CHAT_PROXY_BASE_URL`).
- Agentic text generation uses the **OpenAI Responses API** — `api_backend =
  "responses"`, `POST /v1/responses`. Chat Completions (`/v1/chat/completions`)
  is supported but secondary (web-search helper uses Responses; the sampler
  emits "Sending responses API stream request" for the agent path).
- Debug/curl docs embedded in the binary confirm the chat-completions surface
  too, with the same core auth headers.

### Required headers (from embedded official curl docs)

| Header | Value | Notes |
|---|---|---|
| `Authorization` | `Bearer <token>` | Session token from `~/.grok/auth.json` |
| `X-XAI-Token-Auth` | `xai-grok-cli` | Tells auth middleware to validate as a CLI session token |
| `x-grok-model-override` | `<model>` | Routes to backend; omit-able for `grok-build` (default route) |

### Full header set (from binary header builders / structs)

Confirmed literals (one concatenated field list in the binary):

- `x-grok-client-version` → `1.0.70`
- `x-grok-client-identifier` → `grok-shell` (also lowercase `grok-shell` in
  the `xai-grok-workspace` UA build)
- `x-grok-client-mode` → set on most CLI endpoints (value is mode-dependent;
  the gateway adapter sends `"Desktop"` — the closest 1:1 match to a
  hosted/BYOK runtime)
- `x-grok-agent-id` → per-install id (install-id store)
- `x-grok-req-id` → per-request UUID
- `x-grok-session-id`, `x-grok-conv-id`, `x-grok-turn-idx` → session/conv/turn
  tracking
- `x-grok-transient-retry` → present in the same header list (transient retry
  state)
- `x-authenticateresponse` → `authenticate-response`
- `traceparent` → W3C trace context (`00-<trace>-<span>-01`)
- `x-grok-experiments` → A/B assignment id/arm pairs (`grok inspect` lists
  assignments; sent on every request to cli-chat-proxy "whatever the telemetry
  mode")
- Conditional identity headers (set when a value exists): `x-grok-deployment-id`
  (deployment key), `x-grok-user-id` (user identity), `x-grok-conv-group-id`
  (conversation group).

## Adapter parity (checked-in `src/providers/integrations/grok/`)

The adapter **already matches** the verified wire for agentic text generation:

- Endpoint `/v1/responses`, `wireFamily: "responses"` — matches
  `api_backend = "responses"`.
- `GROK_TOKEN_AUTH = "xai-grok-cli"` — matches `X-XAI-Token-Auth`.
- `GROK_CLIENT_IDENTIFIER = "grok-shell"` — matches `x-grok-client-identifier`.
- `GROK_ALLOWED_FIELDS` — matches the Responses payload field set.
- Headers `x-grok-client-version`, `x-grok-client-mode: Desktop`,
  `x-authenticateresponse: authenticate-response`, `x-grok-agent-id`,
  `x-grok-req-id`, `x-grok-model-override`, `x-grok-session-id`,
  `x-grok-conv-id`, `x-grok-turn-idx`, `traceparent` — all present.
- `reasoning.summary ??= "concise"`, `include: ["reasoning.encrypted_content"]`,
  force-stream, `store` default — match observed CLI behavior.

Gaps (not required for a working request):

- `x-grok-experiments` — A/B assignment header; only meaningful when telemetry
  assigns arms. Not needed for functional parity.
- `x-grok-deployment-id` / `x-grok-user-id` / `x-grok-conv-group-id` —
  conditional identity headers, set only when a deployment key / user identity /
  conversation group exists.
- `x-grok-transient-retry` — present in the CLI's header list; value tied to
  transient-retry state. Unknown semantics; not required for a fresh request.

## Deep-dive additions (2026-11-02, same pinned 1.0.70 binary)

- **HTTP/1.1 confirmed**: `Using HTTP/1.1 for sampling client (force_http1=true)`
  — the CLI's sampler forces HTTP/1.1. Our outbound `fetch` (Bun/undici)
  already dials HTTP/1.1 by default, so no transport change was needed.
- **Request compression**: the sampler's `request_compression.rs` zstd-compresses
  the body and falls back to plain JSON (`zstd compression failed; sending plain
  JSON`). Live-tested: the proxy accepts `Content-Encoding: zstd` (200). The
  adapter now sends zstd bodies.
- **Client-mode enum** recovered: `Generic`, `GrokTUI`, `GrokWeb`,
  `NebulaExtension`, `GrokPager`, `Desktop`. Live-tested all against the proxy:
  every value returns 200 for `/v1/responses`, so `headless` remains accepted.
- **Response field set** (`struct Response with 31 elements`, `CreateResponse`):
  includes `conversation`, `previous_response_id`, `store`, `background`,
  `truncation`, `max_tool_calls`, `stream_options`, `prompt_cache_retention`,
  `user`, `include`, `tools`, `reasoning`, `parallel_tool_calls`, `text`,
  `top_logprobs`, `moderation`, `safety_identifier`, `prompt`,
  `context_management`. The adapter allow-list now lets all of these through.
- **`background` is NOT supported** by the proxy: live `background:true` → 400
  `Argument not supported: background`. Do not send it.
- **`previous_response_id` is NOT supported** for cross-turn continuity: even
  with `store:true` and the real `response.id` of an earlier turn, the proxy
  returns 404 `Previous response cannot be found`. The proxy is stateless —
  conversation continuity is carried entirely by the full `input` history
  (verified: turn 2 with identical session-id but no history lost context;
  turn 3 with full history recalled it).
- **Include values** seen in the wire enum: `reasoning.encrypted_content`,
  `message.output_text.logprobs`, `message.input_image.image_url`,
  `computer_call_output.output.image_url`, `code_interpreter_call.outputs`,
  `web_search_call.results`, `web_search_call.action.sources`,
  `file_search_call.results`. The adapter always sends
  `reasoning.encrypted_content`.
- **`stream_options: {include_usage: true}`** is attached by the shared
  compatible adapter for streaming Responses requests (matches the CLI).
- **`x-grok-user-id`** is sent by the sampler header builder
  (`x-grok-client-version … x-grok-user-id … x-grok-conv-group-id`). The
  adapter now sends it from `auth_state.userId` when present.
- **HTTP 202** could not be reproduced by any request shape we tried (stream
  on/off, store true/false, background, conversation, previous_response_id,
  every model id, both with and without user-id). The only 202 handling in the
  codebase treats it as a quota/exhaustion signal in the feature probe. Likely
  a transient/server-side throttle, not a wire-shape response.
