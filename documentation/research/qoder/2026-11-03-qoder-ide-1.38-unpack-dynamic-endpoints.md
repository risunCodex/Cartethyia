## 3. Dynamic endpoint discovery (chat host is *not* hardcoded)

`sharedProcessMain.js` `ServerEndpointService`:

- `REGION_ENDPOINTS_PATH = "/algo/api/v2/service/region/endpoints"` on center.
- `getDynamicEndpoints()` builds:
  - `inferenceEndpoint` ← `preferredInferenceNode.endpoint` (region config or
    env.json `region_config.preferredInferenceNode.endpoint`), else fallback
    `DEFAULT_DYNAMIC_ENDPOINT` = `api2.qoder.sh`.
  - `nesEndpoint`, `codebaseEndpoint`, `fastModeEndpoint` similarly
    (`preferredNesNode`, `preferredDataNodeMap.codebase`,
    `preferredFastModeNode`).
- Region cache file `region-config-cache.json`, refresh every 1800s.

`agents-window.desktop.main.js` (`AicodingServerRequestService`):

- `getBaseUrl(yf.Inference)` → `getDynamicEndpoints().inferenceEndpoint`.
- Usage: voice polish `{inferenceEndpoint}/api/v2/service/voice/polish`,
  WebSocket `{inferenceEndpoint}/api/v2/service/ws/asr`, telemetry
  `{inferenceEndpoint}/apm`, activity `GET {inferenceEndpoint}/api/v2/activity`.

**Key conclusion:** chat in IDE 1.38 goes through the region-resolved inference
endpoint. The legacy COSY chat path and `/model/v1/chat/completions` are **not
present** as literals in the 1.38 bundles. (Search: `agent_chat_generation`,
`/model/v1`, `chat/completions`, `api2-v2` → all NOT FOUND in
`agents-window.desktop.main.js`, `workbench.desktop.main.js`,
`sharedProcessMain.js`.) The adapter keeps `/model/v1/chat/completions` on
`api2-v2.qoder.sh` as default with COSY fallback (verified live 2026-11-01),
so the adapter and the IDE may differ on chat host — worth noting for future
probes.
