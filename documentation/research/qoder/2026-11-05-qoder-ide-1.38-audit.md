## 1. Ringkasan Eksekutif

Artifact ini adalah Qoder IDE 1.38.0 (stable, release, win32 x64, Electron 42.2.0, dibangun 2026-10-29, commit `1716667cb46594e4c08fc5c502906988efacfc86`, build number `84613112`), di-package dengan Inno Setup 6.4.x. Struktur sudah dirapikan: `out/` berisi UI agent (`lingma/agents-window`, `aura-buddy`, `browser/contrib`, `node/canvasPreview`), `node_modules/` berisi SDK internal `@ali/qoder-config-service-sdk` (0.2.0), `aoq-electron-sdk` (1.2.0-57407598), `@arms/` (RUM/telemetry), dan `adsv`.

Temuan utama:

1. **Permukaan jaringan terpusat di satu map default endpoint.** Bundle berisi `DEFAULT_ENDPOINTS` (`center` → `https://center.qoder.sh`, `quest` → `https://qts2.qoder.sh`, `openApi` → `https://openapi.qoder.sh`, `login` → `https://qoder.com/device/selectAccounts`, `dynamicRegion` → `https://api2.qoder.sh`), semuanya fallback ke `featureFlags.json`. Region discovery aktif (`enableRegionDiscovery: true`) dengan `regionCacheOverridesStaticEndpoints: false` — endpoint hasil discovery **tidak** menimpa endpoint statis.
2. **Identitas mesin adalah blok header Cosy 7-field.** `_buildCosyHeaders()` membangun header `Cosy-Version`, `Cosy-MachineToken`, `Cosy-MachineType`, `Cosy-MachineCode`, `Cosy-MachineId`, `Cosy-MachineHostname`, `Cosy-MachineOS` dari `machineInfoService` (via message extension `aicoding.getMachineInfo`, readable native bridge). Redaksi log mengonfirmasi keberadaan header `Cosy-Key` dan `Cosy-User` juga. Fungsi `qQo()` mensyaratkan SEMUA field terisi (cosyVersion, machineToken, machineType, machineCode, machineId, machineOS, machineHostname) sebelum identitas dianggap lengkap; ada cache persistent `qoderAuth` (localStorage).
3. **Config service SDK (`@ali/qoder-config-service-sdk` 0.2.0)** adalah modul lengkap dan berdiri sendiri: poller HTTP `POST /api/v1/qcs/config/resolve` (ETag/304, interval default 10 menit ±10% jitter, retry exponential 5s×3, single-flight) + SSE client `GET /api/v1/qcs/config/stream?ns=...` (event `connected` / `config:change` / `heartbeat`, reconnect exponential backoff 1s→30s, jitter ±50%), auth probe 10s saat belum login. Base URL per region/env: `openapi.qoder.sh` (global prod), `test-openapi.qoder.sh`, `openapi.qoder.com.cn` (CN prod), `test-openapi.qoder.com.cn`. Namespace feature gate: `qoder-feature-gates` (dari `product.json`).
4. **AOQ SDK (`aoq-electron-sdk` 1.2.0-57407598)** ternyata **bukan** HTTP client — ini SDK RTC real-time (audio/video capture, codec Opus via `PluginOpus.dll`, `alivcffmpeg.dll`, native NAPI `aoq_node_ext.node` + `AoqClientSdk.dll`). Connect memakai **relay endpoints** (`relayEndpoints: [{routeIndex, endpoint, port}]`) + `token`/`sid`/`certFingerprint` — bukan host HTTP biasa. Terhubung ke permukaan voice: `/api/v2/service/realtime-voice/aoq/sessions`, plus WebSocket ASR `/api/v2/service/ws/asr`, dan `/api/v2/service/voice/polish`.
5. **Chat literal legacy & modern TIDAK ditemukan di bundle utama.** String `agent_chat_generation`, `chat/completions`, dan `ChatCompletionStream` tidak ada di seluruh `out/` (grep rekursif kosong). Endpoint yang benar-benar literal di bundle adalah endpoint bisnis/akun (device flow, userinfo, usage, plan, activity, experts, github, remote, plugins, dll). Ini penting: **tanduk chat IDE mungkin dibangun dari fragmen string / berada di extension host (aicoding) / chunk lain**, bukan literal utuh di bundle agent-window.
6. **Col ortogonal dengan adapter Cartethyia:** host, path device flow, jobToken exchange, field machine identity, dan penamaan header `Cosy-*` cocok dengan yang sudah diimplementasikan adapter (intl: `e883ade2-e6e3-4d6d-adf7-f92ceff5fdcb`/redirect `qoder://...`, CN: `e93fe488-5778-4c35-a6fc-0f54ed7b3139`/redirect `qoder-work-cn://`). Perbedaan utama: adapter memakai permukaan chat legacy `agent_chat_generation` + modern + gRPC yang tidak tampak sebagai literal di bundle ini, dan adapter tidak memakai config-service SDK (poller/SSE) atau business endpoints.

**Verdik:** bukti statis mengonfirmasi arsitektur yang sudah di-reverse oleh adapter Cartethyia (device flow PKCE S256, machine identity 7-field, Cosy headers, realm global/CN), dan menambah pengetahuan baru berupa (a) mekanisme config-service SDK (poller ETag/304 + SSE), (b) AOQ RTC voice stack, (c) daftar endpoint bisnis, (d) region discovery.

## 5. Analisis Response

### 5.1 Parsing SSE (bundle agent-UI / config service)

**Config service SSE (SDK `sse-client.js`):** parser manual lengkap:
- Buffer dipecah dengan `"\n\n"`; blok terakhir disimpan sebagai `remaining` (bisa belum lengkap).
- Per baris: `:` (komentar/heartbeat) dilewati; `event: <name>` diambil; `data:` / `data: ` diambil.
- Event yang dikenali: `connected` (→ `onConnected`), `config:change` (data JSON `{namespace, ...}` → panggil `poller.pollNow()`), `heartbeat` (debug), default → log unknown.
- Reconnect: exponential backoff, delay dasar 1s, faktor 2, max 30s, jitter ±50%.

**Chat SSE (adapter Cartethyia, `qoder-sse.ts`):** decoder toleran: event selesai hanya saat payload JSON lengkap (depth balance) atau `[DONE]`; baris kosong di dalam string JSON diperlakukan sebagai literal newline, bukan batas event;  `event:` di-skip; `[DONE]` sentinel akhir stream.

### 5.2 Envelope & error

- Config service: HTTP 200 + `{configs, etag}`; 304 = no-op; non-OK → `ConfigRefreshFailedError` dengan `status`/`responseHeaders`/`responseBody`; `AbortError` = cancel; auth kosong → `ConfigAuthPendingError` (tanpa HTTP request).
- Diagnostic headers response yang dipick SDK: `server`, `via`, `x-request-id`, `x-qcs-request-id`, `x-amzn-requestid`, `x-amzn-trace-id`, `content-type`, `content-length`, `date`. → Menunjukkan gateway di depan service (ingress/API gateway, kemungkinan AWS karena `x-amzn-*`).
- Error chat (dari adapter, verified live): `{"code":116}` = quota (free-tier entitment vs billed), HTTP 402, `Login expired` 403, `10605 isQueued` (parking antrean server-side), `code 101 Signature invalid` (payload tidak canonical-compact). `usage` di-parse dari `raw_usage`; `finish_reason` + reasoning text (`reasoning_content`).

## 6. Proto & Parser

- **Tidak ditemukan** file `.proto` di artifact ini (find `*.proto` kosong, `ChatCompletionStream` literal kosong).
- Adapter Cartethyia men-vendor proto dari **unpacked client lama 1.1.81** (`qoder-worker-runtime.mjs`) di `vendor/qoder-proto/chat.proto` dan `src/providers/integrations/qoder/chat-proto.ts`.
- Service yang diketahui (dari adapter): `model.chat.ChatService/ChatCompletionStream`, host `api2-v2.qoder.sh` (intl) / `gateway.qoder.com.cn` (CN), port 443, channel options: disable HTTP proxy, `default_authority`/`ssl_target_name_override` = host, max message length 32 MiB.
- Shape message (dari adapter `qoder-grpc.ts`): `ChatMessage{role, text_content, tool_calls[{id{value}, call_id{value}, type{value}, function{name, arguments{structValue}}], tool_call_id{value}, reasoning_content{value}}`; `google.protobuf.Value` (stringValue/numberValue/boolValue/nullValue/listValue/structValue); `Struct{fields: Map<string,Value>}`.
- Tool-call stitching: adapter memetakan `tool_calls` dengan `id`/`call_id` StringValue, `arguments` sebagai `google.protobuf.Value` (JSON string → `stringValue`), `reasoning_content` sebagai StringValue — mirror dari helper client desktop `Qat()`/`oBA()`/`jDl()` yang disebut di komentar adapter.

## 7. HTTP/2/3 & Transport Details

- **Config SDK** memakai `fetch` global Node (undici; error chain `UND_ERR_SOCKET`/`ECONNRESET` disebut di kode) + `AbortController`, `ReadableStream` untuk SSE. Tidak ada preferensi eksplisit h2/h3 di SDK.
- **gRPC** (via adapter): `@grpc/grpc-js` — protokolnya HTTP/2 (implisit).
- **HTTP/3/QUIC:** tidak ditemukan string h3/quic/http3 di bundle (belum terverifikasi; lihat §13).
- **WebSocket:** endpoint `/api/v2/service/ws/asr` (ASR voice) tersedia; `liveVoiceUseQcs: true` (featureFlags) + `supportVoiceInput: true`.

## 8. Cosy/WASM Signing & Machine Identity

### 8.1 Machine identity (verified di bundle)

Fungsi `qQo(t)` memverifikasi kelengkapan: `cosyVersion && machineToken && machineType && machineCode && machineId && machineOS && machineHostname`.

`_buildCosyHeaders(e={})`:

```js
const r = await this._machineInfoService.getMachineInfo(e);
const n = r.cosyVersion || this._productService.productVersion || this._productService.version;
const i = r.machineOS || this._getCosyMachineOS();
return {
  "Cosy-Version": n,
  "Cosy-MachineToken": r.machineToken,
  "Cosy-MachineType": r.machineType,
  "Cosy-MachineCode": r.machineCode,
  "Cosy-MachineId": r.machineId,
  "Cosy-MachineHostname": r.machineHostname,
  "Cosy-MachineOS": i,
  "Cosy-…": …  // terpotong
};
```

- Sumber: `machineInfoService` → `sendRequestToExtension({method:"aicoding.getMachineInfo", params, targetRemoteAuthority})` → native bridge (umid). Ini persis mekanisme yang adapter rekonstruksi (`qoder-umid.ts`: runtime-info ELF/PE/Mach-O + seed replay → cosy-machineid/machinetoken/machinetype/machinecode).
- Cache: `qoderAuth` (localStorage key), proses auth shared (`authSharedProcessService`), fallback kosong `{cosyVersion:"",machineToken:"",machineType:"",machineCode:"",machineId:"",machineOS:"",machineHostname:""}`.
- `getCachedLoginMachineIdentity()` → `_readPersisted...` (persisted). Kegagalan `requireComplete:true` → throw.

### 8.2 WASM signer

- **Tidak ditemukan** di sesi ini: string `qoder_auth_wasm_bg`, `withWasmSigning`, `cosyLoginRecoveryPromises` belum di-scan (tidak lengkap); satu-satunya wasm di artifact adalah `esbuild.wasm` (untuk preview online canvasPreview — tidak terkait signing).
- Signing Cosy di adapter: AES-128-CBC + RSA public key PKCS1, body alphabet-scrambled (`QODER_ALPHABET`), canonical compact JSON (keys sorted), signature `Bearer COSY.<payload>.<signature>`, spes `cosy-key`/`cosy-bodyhash`/`cosy-sigpath`. **Di bundle 1.38.0 ini literal signature COSY tidak ditemukan** (kemungkinan di extension host aicoding).

## 11. Temuan Menarik Lain

1. **Redaksi log header sensitive**: kode log deliberately redact `Authorization`, `Cosy-Key`, `Cosy-User` — konfirmasi header-header itu nyata dan dianggap kredensial.
2. **Network diagnosis build-in**: `deviceToken/poll` dengan nonce/verifier tetap `aicoding_network_diagnosis` — fitur diagnostik memakai alur device flow yang sama dengan login sungguhan.
3. **`poller.js` SDK memakai diagnostic headers** `x-qcs-request-id` dan `x-amzn-requestid`/`x-amzn-trace-id` → gateway di belakang config service kemungkinan AWS (Amazon gateway) atau QCS (Alibaba Cloud) — ada dua keluarga trace id.
4. **Config service menggunakan ETag/304 dengan canonical quoted etag** (`"${etag}"`) — protokol kondisional HTTP standar.
5. **featuresFlags**: `supportPersonalTokenLogin: false`, `supportQoderPatLogin: false` — IDE versi ini **tidak** menawarkan login PAT; `qoderDirectAuth: true`, `isQoderByokType: true` (BYOK), `liveVoiceUseQcs: true`, `supportVoiceInput: true`, `supportSecurity: true`.
6. **`remoteAgent/qoder/fix-payloads?token=`** — endpoint perbaikan payload remote (kemungkinan repair failed payloads via token query string).
7. **Trusted domains** hanya `*.aliyun.com`, `*.qoder.ai`, `*.qoder.com`, `*.qoder.sh`, `*.alibabacloud.com` — domain lain diblokir untuk link protection.
8. **`@vscode/deviceid`** dependency → device ID VS Code-style digunakan untuk sesuatu (kemungkinan telemetry).
9. **`adsv`** single index.js di node_modules (belum dibaca; kecil).
10. **`esbuild.wasm`** di `canvasPreview/media/online-preview/` — esbuild WASM untuk kompilasi preview online, bukan signer.
11. **YUVCanvasRenderer** — SDK AOQ punya renderer canvas untuk video; voice/avatar real-time di aura-buddy kemungkinan memakainya.
12. **`agent_common` + `Encode=1`** convention (dari adapter) tidak tampak di bundle; tapi `Encode=1` tidak muncul sama sekali (tidak dicek).
13. **jobToken/exchange berada di openapi v1** (bundle) sedangkan adapter intl memakai center v3 — dua versi endpoint hidup berdampingan; adapter sudah menangani ini via realm table.

## 13. Yang Belum Bisa Diverifikasi

1. **Chat surface internals** (legacy `agent_chat_generation`, modern `/model/v1/chat/completions`, gRPC `ChatCompletionStream`) — literal tidak ada di artifact ini; tidak bisa dikonfirmasi dari bundle 1.38.0. Kemungkinan berada di extension host `aicoding` (tidak ikut di-unpack) atau dibangun dari fragmen string.
2. **Detail signing Cosy di bundle** — AES/RSA/alphabet/secret tidak ditemukan sebagai literal; hanya header `Cosy-*` dan redaksi yang membuktikan keberadaan mekanisme. Algoritma yang diverifikasi berasal dari adapter/donor lama.
3. **WASM signer** — `qoder_auth_wasm_bg`, `withWasmSigning`, `cosyLoginRecoveryPromises` tidak di-scan tuntas (grep spesifik belum dijalankan); satu-satunya wasm = esbuild.
4. **HTTP/3/QUIC** — tidak ada bukti string h3/quic; transport AOQ native tidak dianalisis (DLL tidak di-disassemble).
5. **Client ID & redirect URI device flow di bundle** — tidak dilokasi sebagai literal (hanya diklaim adapter 1:1 dari `Hfl` donor lama).
6. **`adsv/index.js`** — belum dibaca isinya.
7. **Isi `agents-window.js` (20KB) & `agents-window.html`** — bootstrap/UI, belum dibaca penuh.
8. **Perilaku native `AoqClientSdk.dll`** — endpoint relay aktual (host/port default) tidak bisa diekstrak statis dari JS; hanya shape config yang diketahui.
9. **Nilai `Cosy-ClientType` di IDE** — bagian header yang terpotong di grep; adapter memakai `5`.
10. **Kebijakan region discovery runtime** — `regionCacheOverridesStaticEndpoints: false` ada, tapi alur request ke endpoint hasil discovery tidak terlihat di fragment yang di-scan.
11. **`Go-http-client`** — tidak ditemukan (bukan Go client; SDK ini Node/Electron).
12. **Pola `Encode=1`** di bundle — tidak diverifikasi (hanya ada di adapter/donor).
